## Implementation notes

**Genome.** We set a maximum number of nodes and a maximum number of connections than an individual can have, leading to two hyperparameters: MAX_NODES and MAX_CONNS. A consequence of this is that some nodes and connections in my arrays will be “unused” or “disabled”. An individual becomes then seven fixed-length arrays: `node_type`, `node_act` are the node slots, and `conn_in`, `conn_out`, `conn_w`, `conn_on`, `conn_innov` are the connection slots. The slot layout is fixed for a whole run. First inputs, then the bias node then outputs, then free space. A nice consequence of this pytree design is that the same class can be used for both individuals (1-dimensional arrays) and for populations (2-dimensional arrays).

**Forward Pass.** Making the forward pass JIT-compatible was the one of the trickiest parts of the implementation for me (see the Appendix for my forward pass function, oversaturated with annotations). Given an array of inputs, the forward pass needs to match them with the input nodes, which is a little subtle with JAX, since arrays need to stay of fixed size. The solution is to create new pytrees from existing ones by using at[x].set(y) (when we know the index positions) or jnp.where (when we want to use a condition). If a signal needs to go through multiple connections, we use lax.scan. Since a feed-forward neural network has no cycles (viewed as a graph), it needs at most MAX_NODES steps to run the signal through all connections.

**Population initialization.** A generation-zero individual is a minimal network: only bias, input, and output nodes (no hidden nodes). There is only one bias node per individual: it only acts as a source of connections, never a destination, and its output is 1.0 (so it contributes bias x 1.0 = bias to other nodes connected to it). I chose for each initial individual to be fully connected from every input and the bias to every output. A few reasons: it’s simpler to implement, it’s like starting with a linear model (generation 0 is just doing linear regression), and it does not prejudge which inputs matter. I also chose to give random uniform weights in [-2,2] to my initial connections.

**Innovation numbers.** Structural changes are recorded in a record shared across the population, so the same mutation arising independently in two genomes gets the same number. That is what makes genes comparable between genomes, which crossover and the compatibility distance both depend on. My innovation record is a Python dictionary which assigns each distinct structural change a permanent identifier, so that homologous genes in different genomes can be matched during crossover. Without it, two individuals that independently add the same connection would receive different innovation numbers, and crossover would treat those genes as unrelated. I wrote a helper function which looks up or assigns a permanent innovation number to each structural change: if that change has occurred before, it returns the number already assigned; otherwise it assigns the next unused number, records it, and advances the counter. In my implementation, the innovation record persists for the entire run.

**Layer indexing.** I assign every node a layer, and require the destination's layer to be strictly greater than the source's.

**Mutations.** Weight mutations have probability `PROB_MUT_CONN` and are applied with some Gaussian noise, scaled by standard deviation `MUT_SIGMA`. To add a connection between two previously unconnected nodes with a random weight, the idea is to first assign layers to the existing nodes, pick a source, pick a destination in a strictly higher layer that is not already connected, write the new connection in a free connection slot, and stamp the next innovation number. To add nodes, I pick an active connection, disable it, allocate a free node slot for a new hidden node, and add two new connections with the new node in the middle (i.e. `src --w--> dst` becomes
`src --1--> new --w--> dst`). The incoming connection (“on the left”) from the source to the new node gets a weight of 1, while the outgoing connection (“on the right”) from the new node to the destination gets the original weight. This is written into free node and connection slots, and innovation numbers are recorded. The activation function of the new node is randomly chosen from the available list. 

**Crossover** keeps the fitter parent's topology and, for genes both parents share, takes the other parent's weight with probability `PROB_INHERIT_B`.

**Speciation** is what makes complexification survivable. A new hidden node almost always hurts before it helps, so genomes compete mainly against relatives, and fitness sharing stops any one species from taking over. Speciation consists of three functions. First, we compute the compatibility distance between two individuals based on the NEAT formula. Second, we assign every individual in a population to a species, based on the `COMPAT_THRESHOLD` compared with a list of representative genomes from all species in the previous generation. And finally, we divide each individual’s fitness score by the size of its species, so that crowded species have their fitness diluted, and small new species (a fresh topology) are protected from being immediately outcompeted by large established ones.

**Neural Slime Volleyball**. Each generation proceeds as follows. First, every individual in the population plays three games of NSV against the built-in AI, and its raw fitness is the average net score across those games (points won minus points lost over a fixed 1000-step window). All individuals face the same three games, so differences between their scores reflect how well they play rather than luck. I then subtract a complexity penalty proportional to the number of active connections, which shrinks to zero over the course of the run: this discourages networks from growing larger without getting better, while lifting that pressure late on, when score differences have become too small for a fixed penalty to coexist with. Next I group the individuals into species and divide each one's score by the size of its species, so that crowded species are penalized and small new ones (such as those that have just grown a hidden node) are given room to develop. (Because this division only penalizes crowding when the values are positive, I first shift all scores upward so that the worst individual sits just above zero.) Each species is then allotted a number of offspring in proportion to its average shared score. The `N_ELITE` best individuals by raw fitness are copied unchanged into the next generation, guaranteeing that a good solution is never lost to an unlucky mutation. The remaining slots are filled by crossover: within each species, only the better half may be parents, and for each offspring I either combine two parents (with probability `PROB_CROSSOVER`) or clone a single one. When combining, the child takes its entire structure from the fitter parent and inherits some of the other parent's weights on the connections they share. Every offspring then has its weights perturbed slightly, and with small probability gains a new connection or a new node. Finally the new population replaces the old, and the process repeats.

**Backprop NEAT** excludes the step function from the activations a new hidden node may take, since its gradient is zero wherever it is defined. I generate two-circle, spiral, XOR, and Gaussian datasets from the GitHub repo [backprop-neat-js]https://github.com/hardmaru/backprop-neat-js/, using 200 datapoints and a noise of 0.1. These tasks have 2 inputs and 1 output (a tanh); the initial populations also have a bias. The loss function involves binary-cross entropy (the typical loss function used for binary classification tasks) and L2 regularization on the active weights. The L2 weight regularization constant is `L2_REG` and the learning rate is `LEARN_RATE`. The fitness will be negative loss minus a complexity penalty `BP_PENALTY` scaled by the square root of the number of active connections.
